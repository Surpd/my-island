# Квитанция публикации и восстановления

Зависимость — [контракт опубликованной недели, PR 48](https://github.com/Surpd/my-island/pull/48). К подтверждению публикации и исторического восстановления добавлено необязательное поле `operation_id`. Старые клиенты сохраняют прежний контракт. Новый клиент создаёт UUID для подтверждённого preview и при потере ответа запрашивает квитанцию через `GET /api/admin/schedule/constructor/publication/receipts/{operation_id}` под действующей школьной административной сессией. Перед первым POST браузер сохраняет точный подтверждённый запрос и UUID. Хранилище разделено по ключу, выданному сервером для текущего администратора. В нём хранятся только параметры команды. При открытии проверки или истории конструктор сначала ищет квитанцию. Если она ещё недоступна, администратор может проверить её снова или явно повторить исходный запрос с тем же UUID. Отдельное подтверждение остаётся заблокированным, пока исход сохранённого запроса неизвестен.

Ключ, автор, хеш параметров и итог записываются в той же транзакции, что head и архив. Повтор принятой команды возвращает исходный ответ. Повтор ключа с другими параметрами возвращает 409. Устаревшее подтверждение с новым ключом проходит обычную проверку preview. Квитанция доступна только исходному субъекту и включает результат на момент операции.

Миграция 055 добавляет одну таблицу с первичным ключом и RLS. Применяется перед обновлением приложения. Данные существующих публикаций не меняются. SQLite-схема используется в локальных фикстурах. Проверены повтор и подмена параметров с SQLite, а также две отдельные конкурентные транзакции с PostgreSQL 17.11 на loopback. В обоих ответах совпали квитанции, в архиве осталась одна публикация.

На финальной реализации локально прошли 91 тест публикации и административных маршрутов, 6 интеграционных тестов PostgreSQL 17.11, TypeScript и два сценария Chromium. Один браузерный сценарий имитирует обрыв после отправки POST и восстанавливает результат из квитанции с тем же ключом без второй записи.

При смене администратора сервер отклоняет повтор чужой команды. Данные защищены обычной школьной сессией, квитанции возвращаются с Cache-Control: private, no-store. При отклонении устаревшего preview с новым состоянием расписания нужно провести новую проверку. Если браузер запретил запись своего локального хранилища, форма сообщает об ошибке до отправки команды. Очистка хранилища браузера удаляет локальную запись о незавершённой команде, результат уже принятой публикации остаётся в школьном архиве.

Проверки ревью покрывают потерю POST и GET, перезагрузку и повторное открытие конструктора, чтение квитанции без нового POST, точный повтор исходных параметров и отказ при смене администратора. Для восстановления действует тот же контракт. Миграция остаётся 055, обновление API идёт перед frontend.
