# Безопасная нормализация шаблона школы

PR #10 зависит от PR #9 (`codex/elective-campus-blocks`). Нормализатор работает только с отдельной копией шаблона; он не меняет исходный шаблон, недели, выбор основного шаблона и публикации.

## Проверка production read-only

Цель сверена с `.project-identity.json`: Supabase проект `kmrcbewmxeqqxfauiwyy` в `eu-west-1`. Выполнены только SQL `SELECT` по drafts, причинам предупреждений, справочникам групп, преподавателей и назначений. Изменяющих запросов не выполнялось.

| Объект | Ревизия | Занятий | `needsClarification` |
| --- | ---: | ---: | ---: |
| Рабочий шаблон `bef3e5e8-5c6f-4dd9-b1d0-467ce26abe98` | 29 | 357 | 123 |
| Неделя `0637cbfc-2d83-492f-ae7e-3d4816830779` | 3 | 357 | 123 |

Оба объекта содержат одинаковые 357 lesson ID. Агрегатное сравнение показало одно различие `teacherId`; `subject`, `room`, `activityType` и `blockId` совпадают. Недельная копия сохраняется без пересборки и не принимается нормализатором.

### Классификация сохранённых предупреждений

- **44** «Нет подтверждённого назначения преподавателя группе»: все 44 явно указанных преподавателя найдены активными в справочнике; у **13** подтверждено ещё и активное назначение на точную группу и предмет на дату недели. Только эти 13 предупреждений можно снять автоматически. Остальные **31** сохраняются: одного активного преподавателя недостаточно, чтобы доказать связь с конкретной группой.
- **15** «Не подтверждён преподаватель»: у **5** строк указан активный преподаватель, у остальных 10 нет такого подтверждения. В копии можно снять предупреждение только у пяти явных активных преподавателей; записи и назначения не создаются.
- **36** предупреждений об обеде: все 36 ссылок `classId` указывают на существующие активные классные группы. Этот запрос не доказывает, что первоначальный выбор класса в источнике корректен, поэтому предупреждения пока остаются. Ученики из других групп не добавляются.
- **11** ссылок на математические группы: все старые ссылки ведут на существующие активные группы с предметом «Математика», при этом предмет урока отличается. Среди активных учебных групп того же класса с предметом урока нет точного кандидата (**0**); состав не переносится. Администратору нужно выбрать корректную аудиторию либо оставить занятие нерешённым.
- **8** направлений двух исторических блоков `source:B29:electives` и `source:F32:electives` можно привести к явному `activityType=elective`: повторяющийся стабильный ID блока подтверждён, имена и назначения строк не меняются.
- **4** направления цифрового трека уже имеют `activityType=elective`, но не имеют общего `blockId`. Они остаются отдельными и требуют отдельного группового сопоставления в админском конструкторе; нормализатор не объединяет их сам.
- Оставшиеся **9** предупреждений (включая неподтверждённые курсы, программирование/ШУМ, трёхслотовый блок и комбинированную причину) остаются без изменений.
- В рабочем шаблоне **335 из 357** занятий без `activityType`. Их нельзя безопасно классифицировать по названию, поэтому этот инструмент оставляет их нетронутыми и показывает число неразмеченных строк.

Это ограниченная проверка доказательств по текущим справочникам. Она не подтверждает корректность исходной таблицы, фактическое расписание учеников или все конфликты.

## Как работает инструмент

1. Анализирует ревизию и hash payload выбранного шаблона. Для проверки преподавателей делает один пакетный запрос к активным идентичностям и назначениям на дату шаблона.
2. Показывает изменения «было / станет», объяснение, несвязанные направления и число строк, оставленных без классификации.
3. Перед применением сверяет ревизию, hash источника и hash плана. Устаревший просмотр получает HTTP 409.
4. По одному явному подтверждению создаёт новую копию с тем же количеством уроков и ID. Сохраняет provenance источника и доказательств; не выбирает копию основной, не публикует её и не меняет недельные версии.

Повторный preview уже нормализованной копии не повторяет преобразования. Недостаточные доказательства оставляют поля и предупреждения без изменений.

### Изменения Campus

Копия до отдельной публикации не влияет на Campus. Если администратор позже проверит и отдельно опубликует её, восемь строк B29/F32 получат явный elective type и сохранят существующие общие блоки; teacher lanes и комнаты сохраняются. Четыре цифровых направления не объединяются и не показывают выбор курса ученика, пока не сделано подтверждённое групповое сопоставление. Кружки, обеды, SDEP, онлайн и группы этим планом не меняются.

## Проверки

- Backend suite: **621 passed, 13 skipped**, 27 subtests. Адресный React + HTTP E2E в disposable SQLite проверил preview, открытие исходного занятия, подтверждение и отдельную копию: 8 преобразований; в 129-строчном источнике сохранено предупреждение об обеде; исходник неизменён; публикации не было. API regression также проверяет stale preview 409.
- Isolated PostgreSQL **17.12** contract check прошёл: `041` и `042` применены повторно, stale write возвращает 409, publication rollback не оставил частичные записи; дополнительный fixture 357 строк создал копию с 9 evidence-backed изменениями и подтвердил неизменность оригинала. При подготовке схемы migration `016` пропущена из-за повторного `school_source_mappings_protect_manual` trigger, уже созданного migration `015`; полный прогон всего набора схемных migrations не заявляется.
- 357-строчный synthetic preview: **0.553 ms/run** в 1000 последовательных измерениях чистого планировщика Python. Это не production latency; основной DB запрос выполняется один раз на запрос preview/apply, а не на каждое занятие.
- Снимки: [preview с объяснениями](normalization-preview-1366.png), [отдельная копия после подтверждения](normalization-copy-created-1366.png).
- Production publication preview, пересчёт Campus для новой копии и сравнение персональных projections до/после здесь не запускались. Конкретные цифры production preview не утверждаются.

## Ограничения перед релизом

Инструмент автоматически снимает только доказанные причины преподавателя и нормализует исторические elective-блоки. Предупреждения охвата обеда, устаревших групп и неподтверждённого состава курсов сохраняются до решения администратора. Никакие данные production не записывались, недели не перепубликовывались, основной шаблон не переключался.
