**Первым PR стоит закрепить контракт опубликованной недели.** В My Island уже есть единственный указатель на неделю, атомарная публикация, архив, восстановление, разрешение конфликтов в конструкторе и каноническая проекция Campus. Существенные разрывы находятся на границах этих механизмов. Потерянный ответ публикации нельзя надёжно превратить в квитанцию прежней операции; повторная выгрузка изменённой недели намеренно создаёт новую вкладку; устаревшая форма справочника может перезаписать поля другого администратора. Новые экраны должны получать идентификатор опубликованной редакции и полноту её покрытия вместе с данными.

### Как устроена работающая система

Frontend на React 19 и vinext публикуется в GPT Sites. Один административный shell выбирает экран и способ аутентификации; Campus использует ролевые проекции API. FastAPI на Render разделяет HTTP handlers, предметные сервисы и Database для PostgreSQL/SQLite. В production `school_stores()` использует один PostgreSQL для канонических данных и записи. Изолированный тестовый режим использует SQLite; режим локальной разработки с разрешённым read-only школьным источником может хранить черновики отдельно. Отсюда разные условия проверки транзакции публикации и read-only preview. [Выбор хранилища](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/handlers/api.py#L1633) · [Доступ к школьному источнику](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/services/school_experiment_workspace.py#L88)

Шаблон и черновик недели редактируются через experiment store. Текущий выбор основного шаблона хранится отдельно и имеет собственную историю; на его основе создаётся авторская неделя. Публикация компилирует исходник, переносит только разрешённые блоки в canonical-модель, проверяет чтение результата и сохраняет авторский снимок для истории. Указатель действует независимо от открытых пользовательских черновиков. Импорт Google расписания может материализовать редакцию, а выгрузка отправляет документ из My Island в другую книгу. [Выбор шаблона](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/services/school_template_selection.py#L497) · [Атомарная публикация](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/services/constructor_publication.py#L1238) · [Чтение недели](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/services/canonical_schedule.py#L1029) · [Контракт существующей выгрузки](https://github.com/Surpd/my-island/blob/6eda54a79e8606021bfda7385004c8d0e8294218/backend/tests/test_schedule_sheet_publishing.py#L176)

## Б. Где система может дать неверный результат

1. **Совместное сохранение зависит от редактора.** Конструктор различает непересекающиеся изменения и конфликт «удалили/отредактировали». В метаданных документа массив слотов или правила являются одним полем. Во внешнем справочнике человек может сохранить старый набор предметов без предупреждения. Серверу нужна версионная предопосылка и для этих операций. Перевод каждого урока в отдельную новую таблицу не является условием решения.
2. **Один head не описывает все режимы чтения.** В `_effective_week` явное назначение имеет приоритет даже после смены шаблона. Без head, а также при недействительной ссылке, есть выбор последней материализации по дате. `canonical_weekly_refresh.py:792` тоже создаёт материализацию. У `published_week_view` есть фильтр утверждённых статусов; служебный `/admin/schedule/lessons` читает effective_blocks непосредственно. Старый HTTP publish в `api.py:2348` возвращает 410. Это разные гарантии. Нельзя считать любую строку effective_weeks выпущенной недельной редакцией. Повреждённый явный head должен приводить к диагностике; нельзя молча брать другую версию.
3. **Смешение плана, исключения и факта.** Отложенная запись может сделать кабинет «свободным» на экране с неполным покрытием. При отмене в опубликованном представлении assignments пусты. Для дельты нужен исходный блок. Дата работы в журнале и время успешного чтения Google — два разных времени; ни одно не удостоверяет момент ввода оценки учителем.
4. **Расписание как документ Google и как школьное решение расходятся.** Сегодня экспорт привязан к изменяемому черновику, включая параметры оформления. Формально успешная выгрузка может отражать иной состав, чем Campus. У старой задачи после повторной публикации также должна исчезнуть возможность вернуть в лист прежнее состояние.
5. **Стоимость и ошибки сети.** Каждая полная перечитка конструктора, школьной недели или всех персональных проекций даёт лишнюю нагрузку небольшому Render. Индекс или кэш не исправит неверное определение занятия. Сначала нужны единый ключ редакции, пакетное чтение назначений и измерение числа запросов.

## В. Предлагаемая архитектура

### Договор об опубликованной неделе

Backend принимает дату в школьном часовом поясе, возвращает нормализованный понедельник, идентификаторы head/публикации, effective_week_id, базовой версии, ревизию, происхождение, состояние и покрытие. Режимы — ручная недельная редакция, допустимая историческая утверждённая материализация, только базовый шаблон, отсутствует, ссылка повреждена. Только разрешённые первые режимы попадают в показатели опубликованной недели. План по шаблону имеет собственную подпись. Потребителям нужна одна функция выбора существующего артефакта. Внутри одного ответа все запросы привязываются к этому effective_week_id. Персональные проекции сохраняют нынешние фильтры ролей и скрытие персональных сведений.

Публикация продолжает использовать существующие транзакцию, блокировки, preview_token и проверку прав. Добавить клиентский operation_id, уникальную запись с отпечатком входа, actor, результатом и версией head. Повтор того же запроса после проверки доступа возвращает прежний результат, даже если текущая редакция уже сменилась. Повтор ключа с другим телом возвращает конфликт. Успешный commit одновременно фиксирует архив, уведомление об изменившейся неделе и задачу экспорта. При двух публикациях одного preview одна проходит, другой администратор получает информацию о новой версии; перезаписать её можно после нового preview. Restore остаётся новой публикацией, запускает тот же цикл. Глобальную блокировку ослаблять лишь после измерения времени ожидания и проверки связей шаблон → неделя.

### Синхронизация и доступ

Для небольшой школьной команды начать с условного опроса FastAPI: видимая вкладка проверяет версии примерно раз в 10–15 секунд с jitter, при возврате фокуса и online — сразу. Это проектный целевой интервал, подлежит измерению. Один запрос на активную область экрана; неизменившиеся данные возвращают 304 или пустой список изменившихся ключей. Начальная версия может читать head и revision напрямую. Когда появится аудит, использовать транзакционно обновляемую версию области; если вводится курсор событий, обеспечить порядок **commit**, иначе медленная транзакция с ранним sequence id может быть пропущена. При пропуске/истечении курсора делать новую авторизованную сверку. Backoff на сбоях, отметка «данные на …», отмена устаревших ответов при смене контекста.

Для чистой формы можно применить свежую версию. Для открытой формы хранить base, локальные поля, новую серверную версию и identity записи. Использовать существующее трёхстороннее слияние, оставлять фокус и ввод; показать автора, время и изменение конкретного поля. Удаление, перенос, архивирование и массивы требуют собственного сравнения по устойчивым ID. На восстановлении после сетевого сбоя сначала установить исход предыдущей команды. Одно событие содержит только тип, разрешённый ключ и revision; значения и историю возвращает авторизованный API. Ученик и преподаватель читают только новую версию своей публикации. Админские черновики и история доступны после проверки роли. Диагностическая сессия сохраняет сокращённый набор доступов. Удаление роли должно действовать при следующем запросе.

Сохранять actor из проверенной сессии, серверное время, entity/id, старую/новую версии, ограниченный список полей before/after и request_id в той же транзакции, что и запись. Для журнала учётная запись импорта описывает импорт, автор школьной оценки остаётся неизвестным. Ограничить чтение истории и состав чувствительных полей; события и логи не должны содержать ФИО детей или содержимое журналов. Для текущего формата черновика достаточно индекса изменений по draft_id + lesson_id. CAS группы/человека и отдельные семантические команды назначения преподавателя/переноса ученика защищают связанные записи целиком.

**Альтернативы.** SSE через FastAPI может сократить задержку, когда школа подтвердит такую потребность. Нужны переавторизация, повторное подключение и общее хранилище событий при нескольких процессах. Память одного Render-инстанса теряет очередь при рестарте. Supabase Realtime private Broadcast подходит при появлении доверенного короткоживущего JWT, политик на каналы, проверки отзыва роли и потребности в таком масштабе. Миграция 042 запрещает прямое чтение основных таблиц для anon/authenticated. Расширять доступ к таблицам ради уведомлений о черновиках не требуется. Любой push также нуждается в серверной перепроверке версии после разрыва. [Supabase Realtime Authorization](https://supabase.com/docs/guides/realtime/authorization)

### Google Sheets

Ввести привязку (подтверждённая целевая книга, понедельник) → gid видимой вкладки и служебной разметки. Название можно менять без потери идентичности. Для существующих вкладок выполнить read-only инвентаризацию и связывать автоматически лишь однозначный системный marker. Коллизия, собственноручно созданный лист или несколько кандидатов требуют явного сопоставления. Старые вкладки сохранить. Экспорт чернового снимка, если им пользуются, оставить отдельным обозначенным действием.

Долговечное задание хранит publication_id/head revision, попытки, next_retry_at, безопасную причину и состояния ожидает / в работе / выгружено / ошибка / вытеснено. Исполнитель читает immutable published snapshot, сериализует операции **на неделю и книгу**, перед отправкой сверяет head и маркер владения и после записи перечитывает маркер редакции. Обновление значений, очистка старого хвоста и маркер версии идут одним Sheets batchUpdate по тем же gid. Тайм-аут после отправки требует сверки маркера до нового запроса; пока исход старого запроса неизвестен, следующий исполнитель сверяет и при необходимости восстанавливает самую новую редакцию. Фоновая повторная сверка закрывает окно внешних неупорядоченных ответов. Нельзя обещать распределённую транзакцию с Google. Пользователь видит «Опубликовано» отдельно от «Выгрузка ожидает/не удалась». Для одной школы допустим обработчик с редкими повторными запусками и восстановлением из БД; обязательный постоянно работающий новый сервис на первом выпуске не нужен.

### «Сегодня», аналитика и виджеты

| Сервис/показатель | Первая полезная реализация и границы трактовки |
|---|---|
| Операционный день | Расширить текущий /admin. День школы по умолчанию, 7 дней выбранной текущей недели, метка редакции, занятия по времени, подтверждённые замены/отмены и алерты. Каждая строка → publication_id + stable occurrence/issue ID. При смене head доступен переход к новой версии с пояснением. Следующая неделя в отдельной карточке **Черновик** с ревизией, блокерами и ссылкой к конструктору. Не включать её в числа текущего дня. |
| Кабинеты и алерты | Определять занятость пересечением полуоткрытых интервалов [start,end) в нормализованном физическом кабинете. Определять свободу только внутри известного доступного фонда и рабочего времени. До появления полного каталога показывать «занят по опубликованному расписанию», «сведения неполны». Online без физического кабинета, SDEP и обед трактуются по семантике блока. Первые алерты — нет публикации, отложенные занятия, наложение подтверждённых назначений/кабинетов. Ошибка экспорта остаётся техническим статусом. |
| Нагрузка преподавателей, первый аналитический отчёт | Сравнивать план по **прикреплённой базовой версии каждой недели** с выбранной опубликованной редакцией. В отдельном режиме можно смотреть текущий базовый шаблон. Единица — уникальное назначение преподавателя на конкретное занятие с датой и интервалом. Совместный урок с несколькими группами — один для каждого участвующего учителя; один урок с двумя учителями даёт одному уроку у каждого. Человеко-минуты школы и число школьных занятий выводятся отдельно. Считать фактическую длину интервала в минутах, раскладывать лабораторию с продолжением по реальным сегментам, исключать обед, паузы и отменённые сегменты. Преподавание, ответственность за самостоятельную практику и факультативное участие различать. Online, консультации, практикумы, кружки — фильтры формата. Неизвестную длительность/преподавателя показывать отдельным покрытием. |
| Изменение нагрузки | Сопоставлять блоки по происхождению/стабильному ID, назначениям до и после. Для замены A→B на 45 минут показать −45 и +45. При отмене использовать исходное назначение. Отдельная метка для добавления, переноса и изменения длительности; изменение кабинета не создаёт замену. Без надёжной пары показывать несопоставленную запись. В пересечении двух разных занятий показывать конфликт и отдельно назначенные минуты/объединённое время занятости. Drill-down из дня, предмета и группы ведёт к исходной записи редакции. Заголовок «по опубликованному расписанию». Подтверждение проведения занятий в исследованной цепочке отсутствует. |
| Нагрузка класса | Для класса и учебных подгрупп считать число занятий, минуты занятий, размах от первого начала до последнего конца, интервалы без занятий, распределение по предметам/форматам. При параллельных группах считать объединение интервалов для охвата класса и отдельные траектории групп. Общая длительность дня отличается от нагрузки отдельного ученика. Исключить обед и подтверждённые общешкольные паузы из «окон». Опциональные кружки считать отдельно. «Перегружен» — только по согласованному порогу, до него показывать измеренное распределение. |
| Журналы | Считать заполненные результаты по дате **работы**, классу, группе, предмету и журналу. Ноль — выставленное значение, пустая ячейка и сводный балл — отдельные случаи. В знаменатель полноты включать только подходящие активные работы и состав данного маркера группы; отдельно показать несопоставленных, командные записи и подключённое покрытие. Для типов использовать подтверждённые категории источника: О = обязательная, П = пересдача, У = учебная. Приравнивать все О к контрольным можно лишь при подтверждённом правиле источника. Без него показывать «обязательные работы» и покрытие классификации. Историческая динамика **ввода** оценок требует change history на импортируемую ячейку; повторный импорт того же значения не является активностью учителя. Обновлённость — последний успешный sync, ошибка и период. Линки → источник, маркер, работа/строка с повторной проверкой прав. |
| Стоимость чтения | Единая выборка блоков и назначений на диапазон и нужные измерения. Не обходить все personal API преподавателей/учеников и не загружать весь журнал в браузер ради одного числа. Первые агрегаты считать на сервере по запросу. Ключ кэша включает редакции недель, фильтр, роль/область доступа и версию импорта журналов. Ограничивать диапазон, оптимизировать после EXPLAIN и замеров; начальная цель проверки — отсутствие N+1 и повторного расчёта при переключении представления. |
| Персональная раскладка | Каталог в frontend: type, schemaVersion, разрешённые варианты размеров, схема фильтров, доступность ролям и ссылка на общий запрос. В БД одна запись на admin user с версией схемы и CAS, массив экземпляров с instanceId/type/size/order/filters. Один тип допускает несколько экземпляров. Стандартная раскладка из кода, сброс и миграция старых фильтров, неизвестный тип безопасно пропускается. Запрашивать data по нормализованным ключам общих сервисов, группировать одинаковые запросы. Узкий экран перестраивает порядок в колонку. Перемещение/размер доступны кнопками и клавиатурой, drag — дополнение. Настройки не дают прав на чужие данные. |
