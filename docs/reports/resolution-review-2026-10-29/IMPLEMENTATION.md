# Реализация разбора расписания

Работа локальная. Production, feature flags и школьный справочник не менялись; реальное расписание не публиковалось. Отправки Git и выпуска Sites/Render не было.

## Полный источник и безопасные назначения

`schedule_constructor_publications.metadata.published_source` хранит полный payload, fingerprint и реестр всех исходных записей со статусами и кодами замечаний. Он связан с конкретной immutable canonical/effective-версией через запись публикации. Существующая таблица используется без новой миграции.

Разрешённая проекция хранится отдельно: только достоверные назначения получают предмет и участников. Неизвестная аудитория не превращается в целый класс. Для достоверно известного участника нерешённая запись может дать нейтральный маркер `UNRESOLVED` без выдуманного предмета и без раскрытия списка учеников. Маркеры читаются из конкретного опубликованного архива, а не из изменяемого черновика. Старые публикации без архива не реконструируются задним числом.

Сохранены транзакции, CAS ревизии/головы, fingerprint справочника, preview token, проверка обратного чтения и восстановление отдельной новой версией. Проверки чтения и восстановления отклоняют повреждённый источник; повреждённый архив не может установить участника runtime-маркера. Это гарантии приложения, а не запрет прямого SQL для владельца базы.

## Исправления и подтверждения

- Контекст проблемы показывает связанные занятия, точное время, группы, преподавателей и кабинет. Есть переход к записи, исправление кабинета, подтверждение решения и откладывание.
- Кабинеты предлагаются из помещений, встречающихся в черновике. Проверяется весь интервал и остальные записи, включая параллельные занятия и события. Ручной кабинет проверяется повторно на сервере. Изменение производится только кнопкой администратора и поддерживает обычный цикл сохранения и undo/redo. Вместимость, оснащение и фактическая доступность не выдумываются.
- Совместный урок требует одинаковых времени, предмета, преподавателей, общего непустого кабинета и проверенных участников. Ученики остаются в своих исходных аудиториях; Teacher Campus объединяет доказанно совместные строки в логическое событие.
- Самостоятельная практика сохраняет ответственных преподавателей, но исключает их из физической занятости на этом занятии. Student и Teacher Campus получают отдельный формат и имя ответственного. Настоящее двойное назначение остаётся конфликтом.
- Решение сохраняет серверного администратора, время, основание, тип, связанные записи, область шаблона/недели и fingerprint значимых полей, включая фактическое время общего слота. Изменение условий делает подтверждение неактивным. Отмена сохраняет аудит; связанные подтверждения отменяются целиком.
- Обычные create/save API не принимают поддельную историю решений от клиента. Подтверждение выполняет отдельный административный endpoint для конкретных revision и preview token.
- Пересчёт участников показывает сохранённый и текущий состав, изменения и полный список занятий с днём, временем и группой. Массовое действие допускает одно и то же правило аудитории и меняет только snapshots занятий. Memberships школьного справочника не перезаписываются.

## Что требует решения школы

На сохранённой rev45 безопасных назначений осталось 249, полный источник содержит 386 записей. Из 137 нерешённых записей 31 имеет неизвестную аудиторию. Для 26 записей шестого класса доступен просмотр изменения 16 → 17 и явное массовое подтверждение; оно не выполнялось на реальном шаблоне. 34 ученических пересечения и 6 возможных совместных случаев требуют проверки исходных условий. Изменить процент назначения без такого решения означало бы выдумать школьные данные.

78 исходных записей имеют другое занятие с тем же кабинетом в пересекающемся интервале. Для каждой нашлись альтернативы среди 21 известного помещения. В этот счётчик входят и возможные совместные занятия: это число записей для проверки, а не доказательство 78 ошибок. Предложения не применялись автоматически.

## Проверки

- Полный backend через изолированный `backend.scripts.local_test_env`: 564 теста, 9 пропусков; успешный результат. После последних проверок целостности и передачи ответственного отдельно пройдены 60 адресных тестов публикации/решений.
- PostgreSQL 17, только собственный loopback fixture `127.0.0.1:55432/my_island_release_check`: 2 интеграционных сценария прошли, включая все 386 исходных записей, JSONB, history/restore, конкурентное подтверждение, rollback и безопасные проекции. После проверки fixture очищен до схемы и остановлен.
- Локальный аудит rev45: неизменность входного JSON и SQLite проверена побайтно; исторические Student/Teacher projections совпали с legacy для недель 7, 14 и 21 сентября, по 115 учеников и 24 преподавателя на каждую неделю.

Результаты браузерных сценариев, TypeScript, lint и сборки дополняются в README этого отчёта. Скриншоты браузера показывают локальный интерфейс; проверкой Telegram на физических устройствах они не являются.
