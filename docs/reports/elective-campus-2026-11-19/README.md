# Общие блоки курсов по выбору и Campus

Базовая версия: `f2c5ff4ad9c8ea72624d4bfcbf58c23ab5e48bee` (`main`).

## Реализация

- Направления остаются отдельными административными занятиями с собственными преподавателями и кабинетами. `blockId`/`blockName` связывают параллельные направления в один блок; название по умолчанию — «Курс по выбору».
- Администратор может создать общий блок, переименовать его и безопасно сопоставить существующее или историческое направление с блоком. Сопоставление не выбирает курс за ученика и не сохраняет персональных назначений.
- При публикации старое занятие без `activityType` распознаётся как курс только при наличии явного `blockId` и одного из известных названий общего блока. Обычные занятия не переклассифицируются по своему названию или совпадению времени. Неоднозначные записи без устойчивой связи остаются в источнике и получают причину `elective_block_unlinked`.
- Student Campus показывает одну нейтральную карточку на каждый блок и временной интервал, доступный классу ученика. В ней нет направления, списка вариантов, кабинета и преподавателя. Кружки не попадают ни в основные занятия, ни в `optional_activities` Student Campus.
- Teacher Campus по-прежнему получает конкретные занятия из своих назначений; общая подпись блока используется только для ученической проекции.
- Параллельные направления одного блока не конфликтуют между собой по ученикам. Реальные пересечения по преподавателям и кабинетам проверяются по отдельным назначениям, а подтверждённые участники используются для проверки пересечения с обязательным уроком. Неизвестные группы не добавляются в аудиторию.
- Сводка публикации различает исходные строки, карточки Campus, общие блоки и направления, скрытые кружки, неразрешённые персональные назначения и не блокирующие предупреждения. Полный исходный список и версия расписания сохраняются.
- `_admin_week_history()` передаёт `week:%` параметром, совместимым с SQLite и psycopg.

Исходные черновики и production-данные не изменялись. Миграций нет; для поведения интерфейса потребуется frontend-релиз после обычного процесса выпуска.

## Проверки

- Backend: `python -m unittest discover -s backend/tests -q` — **619 тестов OK, 10 пропущено**.
- Адресный Campus E2E: `e2e/campus-optional-activities.spec.ts` — **1 тест пройден**. Проверены общие названия блоков и отсутствие клубов, направления, преподавателя и кабинета в ученической карточке.
- `npx tsc --noEmit` — пройдено.
- `npm run lint` — пройдено.
- `VITE_API_BASE_URL=https://my-island-api.onrender.com npm run build` — сборка пройдена. Vite вывел предупреждения о времени работы плагинов; ошибок сборки нет.
- Регрессия SQL-запроса проверена на изолированном PostgreSQL **17.11**: `LIKE 'week:%'` отбирает недельный ключ, шаблонный ключ не включается. Запускался только локальный скрипт с минимальными синтетическими таблицами. Полный класс `PartialPublicationPostgresTests` не запускался: отдельный пустой fixture со всей схемой для него не был предоставлен.
- Synthetic preview из 357 занятий (7 классов, 175 учеников, 35 преподавателей, 8 направлений, 5 дней): профиль до оптимизации — **5.42 с**, повторный прогон после — **3.42 с** (примерно на 37% быстрее). Это локальный синтетический профиль, не измерение production-недели; на времени есть разброс между прогонами.

## Production-неделя 9 ноября

Чтение production Supabase не выполнено: подключённый Supabase-инструмент не принял доступный `link_id`, а авторизованный read-only доступ к проекту не был подтверждён. Поэтому для недели `0637cbfc-2d83-492f-ae7e-3d4816830779` не заявляются новые числа, классификация отдельных строк или подтверждение исходных связей. Никаких production-записей не читали и не меняли. Покрытие формата проверено синтетическими данными с теми же явными `blockId`/`blockName` признаками.
