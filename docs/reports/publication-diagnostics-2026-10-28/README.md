## Полный реестр и группировки

- [all-386-lessons.csv](all-386-lessons.csv): каждая исходная запись ровно один раз; адрес исходной ячейки, день, точное время, предмет, классы, вид аудитории, размеры сохранённого/текущего состава, статус до/после, собственные коды, причины исключения связанного блока и ключи блоков.
- [summary.json](summary.json): для **каждого кода до и после** — число диагностик, уникальных затронутых записей и блоков, группировки по классам, дням и типам назначений; распределение всех исходных 386 записей и результаты двух dry-run.
- [overlap-evidence.json](overlap-evidence.json): конкретные пары исходных строк, интервалы, предметы, классы, число общих участников/преподавателей; без идентификаторов и имён учеников.
- [roster-evidence.json](roster-evidence.json): доказательство изменения сохранённого состава шестого класса без персональных данных.
- [runtime-verification.json](runtime-verification.json): результаты штатных Student/Teacher-проекторов и сравнения исторических недель.
- [source-integrity.json](source-integrity.json): сверка исходных школьных таблиц, черновика и справочника до/после.

При подсчёте конфликта пересечения учитываются **обе стороны**, а не только запись, на которой выведено сообщение. Поэтому 34 диагностики затрагивают 62 уникальные записи. Одна запись может иметь несколько причин; занятие для нескольких классов учитывается в каждом из этих классов. Эти группировки нельзя складывать как независимые итоги.

## Что было ошибкой алгоритма

### 1. Техническое имя класса превращалось в неизвестный охват

В справочнике класс имеет стабильный ID, техническое `name=grade7:base:7-А` и школьное `base_class_name=7-А`. Компилятор пытался извлечь параллель только из начала технического имени. Для неподтверждённой аудитории запасного списка учеников нет: охват становился пустым. Правило безопасного исключения неизвестного охвата затем убирало другие классы в тот же слот.

Теперь параллель определяется по метаданным **того же canonical ID**: базовому классу, отображаемому имени и известному формату технического ключа. Совпадение похожих названий не используется для назначения учеников.

### 2. Один блок на всю параллель был слишком крупной единицей

Новые редакторские записи без canonical origin группировались только по дню, времени и номеру параллели. Независимые административные классы оказывались в одном блоке и исключались вместе.

Для новых записей ключ теперь учитывает явный набор административных классов. Исходный canonical origin, обе стороны реального пересечения и подтверждённое совместное занятие остаются связанными атомарными единицами. Остаточные аудитории повторно проверяются на всём кандидате; дробление блока не разрешает расширить состав после исключений.

### 3. Служебные флаги проверки смешивались с риском неправильной аудитории

Из 148 исходных `review_required`:

- 49 — уточнение охвата обеда;
- 46 — отсутствие отдельного подтверждения нагрузки при явно указанном действующем преподавателе;
- 22 — преподаватель не указан;
- 31 — действительно неизвестный состав группы или курса.

Первые три категории теперь представлены отдельными замечаниями с сохранением исходных данных. Для обеда нужен известный явный класс. Неактивный/несуществующий преподаватель, произвольная ручная отметка проверки, неизвестный класс и неизвестная аудитория продолжают блокировать соответствующую единицу.

### 4. Две предметные группы ошибочно означали полное покрытие параллели

В понедельник на английском две подтверждённые группы не включают двух остальных учеников параллели. Legacy-проектор объявлял их `UNCOVERED_PARTITION_MEMBER`, хотя исходные строки этим ученикам ничего не назначали. В другом блоке чужая английская разбивка мешала ученику получить его подтверждённый русский язык.

Новые публикации несут явный контракт `audience_coverage=explicit`: выбранные группы не объявляются автоматически исчерпывающей разбивкой всех учеников параллели. Реальные несовместимые пересечения, неизвестные группы и сравнение с подтверждёнными составами проверяются по-прежнему. Если фильтр параллели скрыл бы хотя бы одного подтверждённого участника, проверка проекции отклоняет блок.

Старые опубликованные артефакты без нового контракта сохраняют прежнюю семантику; миграции и перезаписи истории нет.

### 5. Обед конкурировал с уроком и остаточной аудиторией

Обед не являлся учебной занятостью при расчёте состава, но проекция считала его конкурирующим основным занятием. Теперь это fallback: при применимом обычном или остаточном занятии обед для этого ученика не выбирается, в том числе между разными блоками. Для нового контракта используются точные пересечения интервалов; соседние интервалы не пересекаются и длинный урок не сводится к ближайшему звонку.

### 6. Совместные занятия выглядели как двойное назначение преподавателя

Из прежних десяти преподавательских пересечений у пяти пар доказано совпадение предмета, полного набора преподавателей, времени и непустого кабинета. Остальные пять не имели достаточного подтверждения общего места. После исправления границ блоков дополнительно проявилась ещё одна такая подтверждённая пара и ещё одна неподтверждённая.

Подтверждённые пары связываются явным `joint_activity_id`. Исходные составы не расширяются; Teacher Campus объединяет их в одну запись с исходными аудиториями. Повторная копия того же совместного занятия для одного ученика не дублируется. Связь вычисляется заново из текущих данных: устаревший ID из исходной metadata не переносится вслепую.

Пустой кабинет сам по себе — замечание. Но объединение двух независимых назначений преподавателя требует доказательства общего занятия; похожего предмета и свободного текста недостаточно. Разные кабинеты или разные занятия остаются конфликтом.

## Почему оставшиеся случаи нельзя исправить автоматически

**26 записей шестого класса:** сохранено 16 участников, текущий класс содержит 17. Во всех случаях добавился один и тот же действующий ученик шестого класса; удалённых участников нет. Требуется проверить и подтвердить изменение сохранённого состава через штатный пересчёт. Код не расширяет snapshot автоматически и не меняет memberships.

**31 неизвестная аудитория:** 11 записей после удаления неверной математической группы; 8 направлений курса по выбору; остальные — неподтверждённые курсы, программирование/цифровой трек, ШУМ и трёхслотовый блок. Ячейка в колонке класса не подтверждает участие всего класса в элективе. Возврат старой группы по похожему названию создал бы неподтверждённые назначения.

**34 ученических пересечения:** общие участники найдены в сохранённых составах, интервалы в исходных данных совпадают точно. У прежних 32 пар различаются преподаватели; подтверждённых общих catalog ID в исходных 386 записях нет. Например, «Математика» и «Матпроф» не превращаются автоматически в одно занятие или в остаточную аудиторию по названию. Дополнительно найдены две пары одинакового предмета с разными преподавателями и кабинетами: прежняя безусловная льгота для одинакового названия скрывала противоречие и произвольно выбирала одну строку. Теперь такое исключение разрешено только совместимым копиям одного и того же состава, где отсутствующее имя преподавателя/кабинет не противоречит подтверждённой копии. Нужно уточнить реальную разбивку/время либо явно задать остаточное правило. Два уже существующих `available_slot` проверены и не потеряли исходных участников.

## Проверка Campus и неизменности источника

На кандидате в памяти проверены все **115 активных учеников** и **24 преподавателя**: 2541 выбранная Student-активность и 185 Teacher-записей. Полная матрица дня/интервала/предмета/подтверждённого преподавателя сравнена с исходными сохранёнными составами. Неуказанный преподаватель в совместимой копии не означает обязательное отсутствие преподавателя в другой подтверждённой строке того же занятия. Нет лишних назначений, потерь ожидаемых назначений, неопределённых Student-состояний и неразрешённых одновременных Teacher-записей. Совместные Teacher-аудитории объединены без добавления участников.

Старая и новая реализации проекторов сравнены на всех доступных опубликованных неделях с 7, 14 и 21 сентября для всех этих личностей: результаты одинаковы. Отдельно сверены исходные canonical versions/blocks/assignments/effective weeks/effective blocks, публикационные указатели и история, revision/payload школьного шаблона и fingerprint справочника — строки не менялись.

## Тесты и независимая навигация

Полный backend-прогон: **551 тест, OK, 9 пропущены**. После последних уточнений финальный целевой прогон publication + canonical: **63 теста, OK**; он дополнительно проверяет защиту от потери ученика фильтром параллели, устаревшей joint-связи, совпадающих названий при разных преподавателях/кабинетах и выбор подтверждённой копии вместо неизвестного преподавателя. PostgreSQL 17: интеграционный pipeline прошёл, включая новые JSONB-контракты совместных занятий, Student/Teacher readback, rollback, CAS, concurrency и сохранность исторической недели. Использовалась только одноразовая loopback-БД `127.0.0.1:55432/my_island_release_check`; после проверки её данные очищены, кластер остановлен. Новых миграций нет.

Campus выделен в самостоятельную ветку **`codex/campus-navigation-only`**, коммит **`530b253`**, база `c6447d5`. В diff ровно десять frontend/E2E-файлов Campus; новых backend-изменений, панели частичной публикации и нового admin published route там нет. 14 направленных JS-тестов, TypeScript и lint этой ветки прошли. Исходная смешанная ветка не переписывалась.

Эта работа не создаёт нового production-релиза, не публикует неделю и не меняет школьные оценки, группы, назначения, составы или feature flags. Telegram на физических устройствах дополнительно не проверялся. Полнота школьного шаблона остаётся содержательным ограничением: неподтверждённые 137 записей требуют работы с источником, а не отключения проверок.
