## Контракт импорта

Пара книги и ID вкладки определяет источник. Явный префикс определяет период. Название предмета после префикса сохраняется целиком, в том числе у совместного предмета 7 класса. Инструкция классифицируется отдельно. В заголовках встречаются четыре последовательные строки или блок с дополнительными строками и многострочной подписью работы. В части книг группа указана в B строки даты. В строке ученика A содержит имя, B — опубликованный итог, с C идут работы. Для 9 класса инструкция описывает 32 столбца работ C–AH.

Источник определяет итог. Категории У и О имеют доли 40% и 60%, веса работ 1–3. Для О учитывается исходная положительная оценка 3–5 либо первая положительная соседняя П с весом О. Непогашенная обязательная работа блокирует итог, промежуточные результаты сохраняются. Импорт передаёт категории, веса, исходные результаты и опубликованное значение B. Пустое B остаётся пустым. Решение о ручной прибавке в 7 классе остаётся за школой.

## Приёмка и применение

1. Прогнать тест синтетического подключения в backend/tests/test_journal_role_views.py. Он вызывает штатный admin API с подменой только транспорта Google и тестовой аутентификацией, проверяет dry-run без сохранения, два подключения, отсутствие чтений I при импорте II, ручное подтверждение личности и ответ ученического API. В Playwright сценарий «Campus reads the twice-imported synthetic journal from the local API» открывает интерфейс ученика поверх того же локального API и SQLite, с подменой транспорта Google при подключении.
2. После приёмки владельцем выпустить backend и frontend. Миграции схемы для этого изменения не требуются.
3. В «Журналах» открыть форму подключения, выбрать класс и его существующий источник. Нажать «Проверить без сохранения». Сверить количество предметных вкладок с таблицей выше. Проверка подтверждает валидность класса, пары книга/ID, периода, отсутствие дубликатов предметов и разбор. Кнопка импорта активна после успешной проверки для выбранной книги, класса и периода. Сопоставление с сохранёнными работами проверяется при импорте.
4. Начать с одного принятого класса. Выполнить ручной импорт II и повторить его, сравнить числа работ и результатов. Импорт повторяет проверку по свежему чтению всех вкладок. При ошибке проверки ничего не импортируется. Для ошибок записи после успешной проверки сохраняются только успешные вкладки; отката всего пакета в интерфейсе нет. Проверить итог и историю I, пустой II, кабинет сопоставленного ученика и пользователя без сопоставления. Затем повторить по остальным четырём классам. Почасовое обновление для этого прохода не требуется. Оно берёт только ранее включённые источники с привязкой к утверждённому текущему периоду; ручной импорт не меняет этих настроек.
5. При ошибке доступа проверить подключённый школьный аккаунт. При ошибке структуры сверить заголовки блока с инструкцией. При неоднозначных работах оставить сохранённый снимок и проверить идентификацию одинаковых колонок. Повторить вручную после проверки. Для ошибки 11 класса потребуется обезличенная трассировка с типом и местом исключения. Для 10–11 нужны подтверждённые предметные вкладки II и их инструкции.
6. Если требуется изменить серверную метку текущего периода для других представлений, выполнить отдельное действие владельца для каждой проверенной книги. Смена этой метки не нужна для начального выбора II в двух доработанных интерфейсах.

## Проверка в рабочем приложении после выпуска

Предлагаемый порядок классов — **6 → 8 → 5 → 7**. Импорт 9 отложен, пока школа не подтвердит, что можно его запускать или есть надёжный способ не импортировать неподтверждённую вкладку. Для пилота у 6 класса подтверждены 12 предметных вкладок II и нет зарегистрированных ошибок I. После него у 8 класса ожидаются 13 вкладок, у 5 — 11, у 7 — 12, у 9 — 18. Для 10 и 11 классов сначала требуется подтверждение новых вкладок.

В каждом классе завуч выбирает существующую книгу в форме подключения, проверяет её без сохранения, затем запускает ручной импорт II. Это два запроса к `POST /api/admin/journals/connect` с полями `grade`, `spreadsheet_url` из реестра, `term_number: 2`, `auto_sync_enabled: false`. Для проверки передаётся `dry_run: true`, для импорта — `false`. Оба запроса требуют штатную административную сессию. Если предварительная проверка показывает ошибку, сначала проверить указанную вкладку и повторить проверку.

До перехода к следующему классу открыть предмет у завуча и в штатном просмотре от имени сопоставленного ученика. Сверить название и дату одной работы, её тип, вес и оценку с таблицей. Проверить заполненный и пустой итог там, где они есть, и доступ к сохранённому I. Повторить ручной импорт того же периода и сверить количество работ и результатов. При расхождении остановить переход к следующему классу, сохранить статус и проверить связь вкладки и ученика. Приёмку вести по классу и состоянию, без имён и значений оценок в отчёте.
