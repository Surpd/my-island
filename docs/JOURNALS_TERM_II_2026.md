## Контракт импорта

Пара книги и ID вкладки определяет источник. Явный префикс определяет период. Название предмета после префикса сохраняется целиком, в том числе у совместного предмета 7 класса. Инструкция классифицируется отдельно. В заголовках встречаются четыре последовательные строки или блок с дополнительными строками и многострочной подписью работы. В части книг группа указана в B строки даты. В строке ученика A содержит имя, B — опубликованный итог, с C идут работы. Для 9 класса инструкция описывает 32 столбца работ C–AH.

Источник определяет итог. Категории У и О имеют доли 40% и 60%, веса работ 1–3. Для О учитывается исходная положительная оценка 3–5 либо первая положительная соседняя П с весом О. Непогашенная обязательная работа блокирует итог, промежуточные результаты сохраняются. Импорт передаёт категории, веса, исходные результаты и опубликованное значение B. Пустое B остаётся пустым. Решение о ручной прибавке в 7 классе остаётся за школой.

## Приёмка и применение

1. Прогнать тест синтетического подключения в backend/tests/test_journal_role_views.py. Он вызывает штатный admin API с подменой только транспорта Google и тестовой аутентификацией, проверяет dry-run без сохранения, два подключения, отсутствие чтений I при импорте II, ручное подтверждение личности и ответ ученического API. В Playwright сценарий «Campus reads the twice-imported synthetic journal from the local API» открывает интерфейс ученика поверх того же локального API и SQLite, с подменой транспорта Google при подключении.
2. После приёмки владельцем выпустить backend и frontend. Миграции схемы для этого изменения не требуются.
3. В «Журналах» открыть форму подключения, выбрать класс и его существующий источник. Нажать «Проверить без сохранения». Сверить количество предметных вкладок с таблицей выше. Dry-run проверяет чтение и разбор, сопоставление с сохранёнными работами проверяется при импорте.
4. Начать с одного принятого класса. Выполнить ручной импорт II и повторить его, сравнить числа работ и результатов. Проверить итог и историю I, пустой II, кабинет сопоставленного ученика и пользователя без сопоставления. Затем повторить по остальным четырём классам. Почасовое обновление для этого прохода не требуется.
5. При ошибке доступа проверить подключённый школьный аккаунт. При ошибке структуры сверить заголовки блока с инструкцией. При неоднозначных работах оставить сохранённый снимок и проверить идентификацию одинаковых колонок. Повторить вручную после проверки. Для ошибки 11 класса потребуется обезличенная трассировка с типом и местом исключения. Для 10–11 нужны подтверждённые предметные вкладки II и их инструкции.
6. Если требуется изменить серверную метку текущего периода для других представлений, выполнить отдельное действие владельца для каждой проверенной книги. Смена этой метки не нужна для начального выбора II в двух доработанных интерфейсах.
