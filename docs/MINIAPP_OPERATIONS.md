# Mini App: роли и административный предпросмотр

## Основные маршруты

- `/` — существующие Student Campus и Teacher Campus. Переключатель показывает только собственные роли, возвращённые сервером; выбранные роль, экран и дата сохраняются в адресе.
- `/admin` — современная админка, включая вход из Telegram и браузерную сессию через Telegram.
- `/admin/preview` — поиск школьной личности, выбор ученика/учителя, даты и размера телефона. Действие «Посмотреть приложение» также доступно в карточках школьных учеников и преподавателей.
- На узком экране административное расписание показывает опубликованную неделю; полный конструктор остаётся доступен на широком экране.

Предпросмотр запускает тот же Campus в iframe. Telegram-аккаунт выбранного человека не требуется. В адресе можно передать `identity_id`, `kind=student|teacher`, `day=YYYY-MM-DD`; это параметры выбора, а не разрешение на чтение.

## Авторизация и завершение

Сервер создаёт сессию через `POST /api/admin/previews`, привязывает её к администратору и ограничивает срок одним часом. Каждый запрос с `X-Preview-Id` заново проверяет владельца, срок, состояние и школьную личность. Записывающие запросы с заголовком предпросмотра запрещены. Просмотр не выдаёт дополнительные роли и не создаёт Telegram-пользователя выбранному человеку.

Кнопка завершения, смена человека и уход со страницы завершают сессию через `/api/admin/previews/{id}/end`. При сетевой ошибке доступно повторное завершение; серверный срок действует независимо от браузера. Идентификатор сессии и авторизация не помещаются в URL. Обмен конфигурацией iframe проверяет источник окна и origin.

## Источники данных

Расписание читает опубликованные effective-недели canonical pipeline; неопубликованная неделя не подменяется черновиком. Журналы используют нормализованные результаты и сопоставления школьных личностей. Диагностика отдельно показывает источник, группы, состояние недели и сопоставления журналов. Ошибка загрузки не обозначается как отсутствие оценок.

В изолированном локальном тестовом режиме источник явно подписан как тестовая база. Сценарии используют синтетические личности, опубликованную тестовую неделю и разные результаты двух учеников.

В локальном режиме чтения школы `SchoolPreviewDatabase` читает подтверждённый Supabase через транзакции `READ ONLY`. Временные preview-сессии и их аудит хранятся отдельно в `.local-test/school-preview.sqlite3`; туда не копируются ФИО, группы и оценки. Вход по одноразовому Telegram-коду использует существующий механизм авторизации: он изменяет только состояние входа, не школьные сведения. Проверка уже выданной браузерной сессии не обновляет `last_seen_at` в источнике. Новые пользователи и роли здесь не создаются. Обычная БД без этого адаптера по-прежнему получает **409** в локальном школьном режиме.

Transaction pooler Supabase на порту 6543 требует отключения автоматических prepared statements psycopg (`prepare_threshold=None`). В read-only адаптере это настроено явно; обычное подключение отключает их только для transaction pooler, сохраняя настройки session/direct-подключений.

## Локальная проверка

```powershell
$env:MY_ISLAND_TEST_PROFILE='manual'
npm run dev:local
```

Изолированный E2E runner использует собственную тестовую БД и порты. Для точных команд см. `package.json` и `scripts/run-e2e.mjs`; новые сценарии находятся в `e2e/miniapp-preview.spec.ts`.

```powershell
python -m backend.scripts.local_test_env test
npm run lint
npx tsc --noEmit --pretty false
$unitFiles=@(rg --files components e2e -g '*.test.mjs')
node --test @unitFiles
```

Production-сборка требует явный `VITE_API_BASE_URL`. Frontend публикуется через GPT Sites, backend — через Render. Перед внешним действием сверять все поля `.project-identity.json`; Git push не публикует frontend. Эта интеграция не требует новой миграции.

Для обезличенной проверки реального источника после сверки принадлежности проекта:

```powershell
python -m backend.scripts.school_integration_smoke --week-start 2026-09-21
```

Команда читает реальные профили, группы, нормализованные журналы и canonical-проекции, выводит только счётчики и статусы. Она не заменяет проверку авторизации и интерфейса. Production-релиз и физическая проверка Telegram BackButton/safe areas остаются отдельными этапами; порядок выпуска описан в `SCHOOL_INTEGRATION_RELEASE.md`.
