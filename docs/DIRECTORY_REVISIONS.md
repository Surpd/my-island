# Версионные правки справочника

[Draft PR #49](https://github.com/Surpd/my-island/pull/49) реализует задачу 4 архитектурного плана от 25 ноября. База — main. Для проверки используются синтетические записи.

## Договор API

* Карточки и коллекции групп, учеников и преподавателей возвращают целочисленную `revision`. Клиент запоминает её при открытии формы. При редактировании, архивировании, восстановлении и изменении отношений он отправляет `expected_revision`. Созданию новой записи исходная версия не требуется.
* Правка предметов, назначений или членства изменяет версию соответствующего человека. Изменение состава или назначения также изменяет версию связанной группы. Версия монотонна, число приращений не обозначает число нажатий на кнопку.
* В группе `add_members` принимает список объектов с `identity_id` и `expected_revision` ученика. Название, предмет, назначение и отмеченные ученики сохраняются одной транзакцией, включая сценарий создания группы. Один конфликт отменяет весь запрос.
* Для устаревшей версии API возвращает HTTP 409 с `detail.code=directory_revision_conflict`, текущей основной записью и сообщением для формы. Полную актуальную проекцию отношений клиент получает при повторном чтении. Пропущенная версия возвращает HTTP 428. Удалённая сущность возвращает HTTP 404. Черновик редактора остаётся в форме при сетевой ошибке и конфликте.
* История доступна администратору через `GET /api/admin/directory/history/{identities|groups}/{id}` и аналогичный маршрут под `/api/admin/school`. Ответ содержит последние 100 изменений от новых к старым, автора, время, версию и имена изменённых полей. Значения полей в эту историю не записываются. Системные изменения вне транзакции редактора имеют пустой actor_id.
* Для нескольких изменений в одной карточке действует конфликт на уровне карточки, в том числе когда администраторы меняли разные поля. Редакторы разных карточек могут сохранять независимые изменения.

## База и порядок выпуска

Миграция `054_directory_revisions.sql` добавляет версии с начальным значением 1, таблицу истории и триггеры для обеих основных сущностей и пяти таблиц отношений. До миграции прежние изменения истории полей недоступны. PostgreSQL блокирует строку агрегата и повторно проверяет версию под блокировкой. SQLite использует транзакцию с `BEGIN IMMEDIATE`. Неудачная операция откатывает связанные записи, версии и историю вместе. Явные роли доступа к таблице истории ограничены сервером. SQLite обновляется через штатную инициализацию локальной схемы.

Выпуск требует отдельного решения владельца. Сначала применяется миграция 054, затем необходимо согласованно выпустить совместимые API и обе формы. Старый открытый клиент при первой попытке исправить запись после перехода получит 428 и инструкцию обновления. Длительные обновления отношений могут на PostgreSQL войти во взаимную блокировку. Транзакция проигравшего редактора откатывается, клиент получает конфликт и может повторно открыть запись.

## Проверка

* `backend/tests/test_directory_revisions.py` — конкурентное сохранение двух разных списков предметов, неизменившийся повтор, изменение назначений с инвалидированием обеих карточек, откат SQL-транзакции и групповой записи, устаревшая версия, обязательная версия, права и минимизация значений в истории. Пять общих сценариев запускаются и на SQLite, и на отдельном PostgreSQL 17.11.
* Профиль PostgreSQL использует отдельный пустой кластер на loopback, порт 55438 и базу `my_island_directory_check`. В тестовом кластере применены репозиторные миграции 001–010, 013, 020–021, 034–037, 054. Для запуска надо явно передать соединение в `MY_ISLAND_DIRECTORY_TEST_DATABASE_URL`. Без этой переменной пять PostgreSQL-тестов пропускаются.
* На SQLite и PostgreSQL выполнено 34 теста в четырёх модулях: `test_directory_revisions`, `test_school_directory_admin_projection`, `test_school_directory_api`, `test_admin_console`. TypeScript прошёл проверку `tsc --noEmit`.
* Браузерные сценарии — создание и изменение группы, архив, перенос ученика, изменение класса, конфликт в двух независимых контекстах Chromium. Сценарий сохраняет второй ввод после HTTP 409 и проверяет через API, что в базе осталась первая версия. Дополнительно проверяется сетевой отказ до сохранения.

## Дополнительная проверка альтернативных записей

`POST /api/admin/homeroom-assignments` требует одновременно `expected_revision` преподавателя и `expected_group_revision` класса. Обе версии проверяются под блокировкой до записи назначения и аудита. Устаревшая форма получает 409, запрос без версии получает 428. Триггер по `class_group_id` обновляет обе карточки даже при изменении через другую службу. Миграция 054 исправляет прежний PostgreSQL-триггер валидации, который обращался к отсутствующему у классного руководства столбцу `group_id`.

Административный маршрут истории возвращает `field_values` с парами `before` и `after` для типа, статуса, признака канонической группы и активности связи. В предыдущих строках значение по умолчанию — пустой объект. Имена, комментарии, причины правки и исходные строки импорта в пары значений не входят. Для текстовых полей доступно название изменённого поля. Транзакционный откат удаляет и изменение, и соответствующую запись истории.
