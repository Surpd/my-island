# Совместная работа администраторов

[Draft PR #59](https://github.com/Surpd/my-island/pull/59) реализует пункт 5 плана. Базовая ветка — codex/directory-revisions, [PR #49](https://github.com/Surpd/my-island/pull/49). Применяется схема 054 из базового PR. Дополнительная миграция для совместного редактирования не требуется.

## Обмен изменениями

Активная страница раз в 15 секунд запрашивает метку версии. Возврат фокуса, появление сети и показ вкладки инициируют внеочередную сверку. Одновременно исполняется один запрос. Скрытая вкладка пропускает опрос. При неизменной метке полное содержимое повторно не загружается. Ошибка сети оставляет метку неподтверждённой. После восстановления сети клиент повторяет чтение.

* Обычный и школьный `GET /api/admin/[school/]directory/version` доступны только соответствующему администратору. Ответ содержит идентификатор подтверждённого администратора и SHA-256 от упорядоченных ключей и версий групп и людей. Метка меняется и при удалении. Получение версии читает по одной паре ключ/версия на карточку. Рост размеров справочника требует измерения этого запроса.
* Существующие школьный и обычный GET черновика конструктора принимают `revision_only=true`. Тогда сервер выбирает только revision и возвращает её вместе с идентификатором администратора. Полное чтение дополнено `viewer_id`. Проверки школьной сессии действуют и при коротком чтении.
* Потеря доступа или смена личности закрывает административный экран. Диагностический клиент не подписывается. Сессии школьных ролей не могут получить метку черновика.

## Что видит редактор

Справочник обновляет список в фоне. Открытые поля и выбранные ученики остаются на месте. Если за это время изменилась открытая группа или преподаватель, форма предлагает сравнить данные. Изменения непересекающихся полей переносятся вместе. Для поля, изменённого обеими сторонами, требуется явный выбор. При наличии записи истории показываются автор и время. Применение выбора обновляет локальную форму. Запись на сервер происходит только после сохранения и под проверкой версии, в том числе при повторном конфликте. Удалённую запись нельзя незаметно создать заново. Выбор чужого удалённого назначения требуется подтвердить заново в актуальной карточке.

Конструктор получает полное содержимое только для новой версии. Для независимых изменений используется существующая функция mergeScheduleDrafts. При пересечении правок открывается существующий диалог конфликтов. Активный ввод инспектора откладывает фоновое объединение, сохраняя фокус. История локальной отмены обнуляется после получения внешней версии, чтобы отмена не возвращала сервер к устаревшей сетке. Ключ локального восстановления ограничен личностью администратора, пространством и черновиком. Старые копии без установленного владельца автоматически не открываются. Справочник сохраняет незавершённое редактирование в памяти вкладки при разрыве соединения, данные школьных карточек не записываются в браузерное хранилище.

## Проверяемые сценарии

* `test_directory_live.py` проверяет появление/изменение/удаление записи, неизменившуюся метку, отзыв сессии, права чтения версии черновика, сокращённую форму ответа и отсутствующий черновик.
* `directory-live.spec.ts` работает с двумя изолированными браузерными контекстами и разными администраторами тестовой SQLite. Второй редактор сохраняет фокус и несохранённый текст после отключения и восстановления сети, получает автора и выбирает значение конфликтующего поля. Итог и автор повторной записи проверяются через API.
* Существующие браузерные проверки редакторов и набор SQLite/PostgreSQL из PR #49 входят в GitHub Actions этого PR. Для проверки протокола используются только синтетические записи в изолированных экземплярах.
