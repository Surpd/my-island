# Приёмка второй итерации

## Независимая критика и внесённые изменения

Независимый рецензент просмотрел отрисованные экраны журнала, доски и оперативного дня и проверил мобильные правила по критериям Impeccable. Приоритеты отражают экспертную оценку. Исследования с сотрудниками школы ещё не было.

| Наблюдение | Изменение и способ проверки |
|---|---|
| Две полные матрицы конкурировали за внимание. В Д добавлялся длинный список работ. | Командная матрица С/Д свернута с указанием объёма. Раскрытие показывает все работы. В С можно перейти на сводку. В Д на телефоне закреплён селектор текущей работы. Сравнить две соседние оценки и затем одну работу. |
| Мобильные кнопки дат и журнала были мелкими, части подписей не хватало. | Контролы периода/работы и даты дня проверены на цели 44 px. Классы имеют видимые названия. На телефоне даты прокручиваются внутри ряда. |
| Жёлтые административные классы и учебные группы могли восприниматься как одинаковые сущности. | На доске С есть явные заголовки; при прокрутке на узком экране сохраняется контекст параллели. Проверить поиск и возврат из состава. |
| «Сегодня» одновременно выделял несколько вторичных блоков. | Перед хронологией на телефоне стоят требующие внимания изменения. Краткое состояние черновика и неполного покрытия видно до раскрытия подробностей. У отмены и замены есть текст. |
| При дополнительной визуальной сверке варианты профиля и формы отличались преимущественно порядком колонок. | В Д профиль начинается с недельного расписания с выбором дня. Длинная форма Д разбита на шаги и итоговую проверку; С оставляет редактирование на одном листе. |
| Аналитика вводила отдельный бирюзовый акцент, а переход из профиля мог сменить человека в preview. | Основной акцент возвращён к синему My Island; при переходе в preview сохраняются имя преподавателя и его роль. Изображение Campus обозначено как статичный образец. |

## Браузерные проверки

[Подробные замеры по каждому экрану](verification.json) · [Сценарий замеров](verify.cjs). Chromium открывает локальные HTML-файлы. Проверяются 8 экранов в трёх вариантах, пять новых рабочих разделов и сама страница приёмки. Ширины 390, 768, 1366, 1440 и 1920 px. Высота окна 900 px. Итоговый прогон — 150 сочетаний: 0 ошибок JavaScript и загрузки, 0 переполнений страницы, 0 обнаруженных axe-core нарушений для набора WCAG 2.0/2.1 A и AA. Полноразмерные снимки сняты при ширине 1440 px. Прокрутка широкой таблицы допустима внутри таблицы.

| Сценарий | Проверено |
|---|---|
| Каталог → журнал → период → назад | С и исходный образец открывают предмет одним выбором, в Д выбор и открытие разделены. Проверены пустой период, поиск, технический диалог, Escape и возврат к каталогу. |
| Исправление источника и сопоставление | Неверная/допустимая ссылка, повтор синхронизации, сопоставление записи из другого класса с подтверждением, связь группы. Проверены демонстрационные состояния без сети. |
| Журнал на узком экране | Выбор работы, переключение на матрицу, сводные колонки и раскрытие командных результатов. Строки таблицы остались плотными при увеличенных интерактивных целях. |
| Справочник и профиль | Вход в состав, поиск, сохранение назначения, выбор дня. Переход из профиля Лебедевой в preview сохраняет имя и роль «Учитель». |
| Длинная форма | Невалидная отправка, пошаговая проверка, возврат с сохранением ввода, сохранение исправленной записи. |
| Рабочий день и аналитика | Пересечение занятости кабинета, выбор исключения, отдельная детализация преподавателя и работы. |
| Виджеты и preview | Добавление с сохранением раскладки, смена роли и имени; рамка Campus доступна с клавиатуры и прокручивается клавишей End. |

**Как читать число действий.** В JSON это количество доступных ссылок, кнопок, полей и пунктов раскрытия в видимой части рабочей области. Счётчик включает кликабельные строки с данными. Он не измеряет время и не равен числу управляющих кнопок. Например, при 1366 px видны 16 элементов в форме C и 5 в первом шаге Д. В таблице преподавателей С — 22, а в Д — 32 из-за предметной группировки. Для повторной массовой правки одношаговый С требует меньше переходов. Для редкого сложного ввода Д даёт проверку перед сохранением.

## Инструменты и воспроизводимость

- [Impeccable](https://github.com/pbakaus/impeccable) запускался локально. Применены playbook critique, distill, quieter, clarify, layout, typeset, polish и harden. Убраны конкурирующие акценты, переписаны состояния, проверены формы и ошибки. Отдельно запускался статический детектор.
- [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) проверен поиском локальной базы UX. Для широких таблиц выбрана прокрутка внутри области, для форм — локальные ошибки и возврат к вводу. [Frontend Design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) применён при выборе композиции, крупных заголовков и типографики. Этот инструмент состоит из инструкций, отдельная программа для запуска не нужна.
- [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines) сверены с актуальным документом: нативные интерактивные элементы, видимый фокус, подписи полей. [Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance) вернул руководство по диалогам из CLI. Проведены браузерные проверки открытия, закрытия и клавиатуры.
- [Google Stitch](https://github.com/google-labs-code/stitch-skills) установлен как набор инструкций; в этой сессии нет авторизованного MCP-подключения или доступного ключа Stitch. Варианты созданы и сравнены в HTML. [Официальные условия подключения SDK](https://github.com/google-labs-code/stitch-sdk).
- OpenPencil desktop не предоставил открытого документа. Установленное локальное ядро OpenPencil 0.17.0 экспортировало файл FIG и прочитало его повторно. На доске 2 страницы, 21 редактируемый экран и 1488 текстовых слоёв. Снимки защищённого конструктора встроены отдельно.
- Diagram Design применён к [схеме школьного дня](reading-day.svg). Playwright и [axe-core](https://github.com/dequelabs/axe-core) проверяют работающий HTML. axe-core 4.14.1 установлен отдельно от приложения. Для повторения нужен установленный Chromium Playwright и пакет axe-core, либо путь к его скрипту через `AXE_CORE_PATH`. Запуск из каталога материалов — `node next/verify.cjs`.

Проверки относятся к стартовым состояниям и перечисленным маршрутам. Серверные права, реальная синхронизация, публикация и проверка безопасности школьных данных принадлежат функциональным PR. Регрессия на рабочих данных и проверка со скринридером нужны при внедрении.
