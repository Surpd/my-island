# Ученики, группы и преподаватели

Исходники для сверки состава действий — [SchoolDirectoryAdmin](../../../components/school-directory-admin.tsx), [TeacherDirectoryAdmin](../../../components/teacher-directory-admin.tsx), [логика агрегации назначений](../../../components/teacher-directory-logic.ts), [реестр цветов преподавателей](../../../components/teacher-color-registry.ts). Компоненты на маршрутах администратора использованы как опорное состояние S. S воспроизводит структуру текущих экранов на той же синтетике, включая доску групп с отдельной полкой классов, фильтры, список с переключателем вида и профиль с вкладкой «Основное» по умолчанию. Пиксельной копией текущего интерфейса S не является. В прототипе 14 классов, 28 учебных групп, 308 учеников и 29 преподавателей на общей выборке. Нагрузка показана только в S как отсутствие данных. Уроки в профиле иллюстрируют навигацию по источникам, их количество не является аналитической метрикой.

Частота ниже — рабочая гипотеза по сценарию завуча. Школьные данные доступны с административной школьной сессией. Операции записи дополнительно требуют доступности записи и соблюдения ограничений соответствующего источника. Изменения в прототипе хранятся в течение просмотра до перезагрузки.

## Решения по макетам

- **Ученики и группы — C.** Параллель видна одновременно с административными классами и учебными группами. D стоит проверить на сценарии предметного распределения через несколько параллелей. Панель состава оставляет контекст доски, а на узком экране следует перед доской.
- **Преподаватели — C.** Поиск по фамилии и просмотр нескольких предметов упрощает таблица. D полезен при формировании команды предмета, но основной предмет в карточках требует выбора при внедрении. Переключатель вида оставляет доступ к обоим представлениям.
- **Профиль — C.** Первый экран отвечает на вопрос о школьной деятельности. D показывает рабочую неделю с выбором дня и только затем назначения. Сведения об источнике расположены у назначения и раскрываются по запросу.
- **Формы — C.** Поля и ошибки в основной колонке, пояснение в соседней. На мобильном пояснение следует за формой. D ведёт через основное, параметры и проверку перед сохранением, сохраняя введённое при возврате. Синтетический сценарий проверяется сразу при уходе из поля и выдаёт фокусируемый список ссылок на незаполненные поля.

Из поиска UI/UX Pro Max использованы встроенная проверка поля при уходе из него и фокусируемый свод ошибок при отправке формы. По результатам сверки текущих компонентов повторный переход к группе и повторные ссылки на конструктор объединены. Удаление источников или школьных операций к внедрению не предлагается. Ошибки соединения, коллизии данных и частичные ответы описаны как интеграционные сценарии, демонстрация использует локальный набор.
