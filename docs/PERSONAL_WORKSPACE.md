# Серверный контракт персонального пространства

База — [оперативный день, PR 54](https://github.com/Surpd/my-island/pull/54). Для работы всех виджетов нужен [расчёт нагрузки, PR 53](https://github.com/Surpd/my-island/pull/53). Клиентская синхронизация нескольких окон зависит от [PR 59](https://github.com/Surpd/my-island/pull/59). Оформление и перемещение средствами интерфейса относятся к следующей поставке после выбора визуального направления.

GET /api/admin/workspace/layout возвращает только настройки текущего администратора, каталог, версию схемы и ревизию. Порядок элементов widgets определяет порядок на экране. Один тип можно добавить несколько раз с разными фильтрами и размерами compact или wide. Таблица requests связывает нормализованный URL защищённой выборки с экземплярами, которым нужен одинаковый ответ. При отсутствии фиксированных дат день и неделя вычисляются в школьном часовом поясе во время чтения. Каждый источник проверяет роль и актуальность отдельно.

PUT принимает expected_revision, schema_version (1) и widgets. Пустой список сохраняет пустое пространство, null восстанавливает стандартный набор и увеличивает ревизию. При гонке один запрос проходит, второй получает HTTP 409 с текущим документом. Параметр владельца отсутствует. Ответ помечен private, no-store. Для устаревшего сохранённого типа виджета чтение пропускает его экземпляр. Ссылки на удалённые сущности разрешаются уже самим источником данных.

Миграция 058 добавляет admin_widget_layouts с первичным ключом по пользователю и RLS. Новые пользователи читают стандартный набор без записи в БД. Применение к production — отдельный этап. Интеграционные сценарии покрывают две личности администратора, три экземпляра с двумя запросами, конфликт, сброс, запрет школьных ролей, фильтры и конкурентную первую запись.
