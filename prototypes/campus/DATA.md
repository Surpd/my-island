# Данные и функциональный план кампуса My Island

Срез контрактов проверен по `origin/main` на `5843f685fc18ed8ddcc158c299d4aca097831bbf` (28 ноября 2026). Ссылки на исходники — GitHub permalinks к этому коммиту в настроенном `origin` (`https://github.com/Surpd/my-island`); сетевую доступность ссылок в этой проверке не проверяли. В прототипе используются вымышленные имена, группы, события и результаты. Доступность реальных данных зависит от публикации расписания, сопоставления журнала и синхронизации Classroom.

## Порядок реализации

1. Подключить read API для обеих ролей. Проверить прямые переходы, возвращение к выбранному дню/предмету/группе и независимые состояния загрузки, пустоты, ошибки и отсутствия подключения.
2. Согласовать и покрыть тестами малые правки контрактов. Вернуть режимы дня учителю, очистить DTO домашки и ограничить его актуальным доступным coursework, поправить связь истории по идентификатору. Проверить пустой/архивный период, баллы 0, статус без числа и отсутствие результата, день онлайн/SDEP и неопубликованную неделю, учителей без класса и запрет запроса чужой группы.
3. Отдельно решить работу с данными из БД для вложений, заданий учителя и сводки куратора. Проверить просмотр в пределах назначений для обычной и админской read-only preview-сессии. Существующие учительские и ученические write-запросы попадают в защитный fallback. [Защита preview](https://github.com/Surpd/my-island/blob/5843f685fc18ed8ddcc158c299d4aca097831bbf/backend/handlers/api.py#L3105)
4. Для функций записи согласовать школьные правила и систему хранения. Приоритетные решения — синхронизация с Classroom, источник оценок, отметки объявлений и доставка. Действия с внешними сервисами требуют сверки с идентичностью проекта.
